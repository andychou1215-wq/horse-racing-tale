# MVP原型範圍

## 目標
docs/ 底下的系統已經相當完整，但範圍太大不適合一次全部做。這份文件定義「最小可行原型」要驗證的核心問題：訓練→比賽→成長→再訓練這個核心迴圈，玩起來是否有感、比賽結果是否合理、數值成長曲線是否有意義。不追求內容廣度，先把核心迴圈的手感做出來，再決定要往哪裡擴充。

## 保留(MVP必須有)
- 馬匹11項屬性、跑法適配度、體力系統(比賽公式.md/體力系統.md/馬匹系統.md) — 核心數值引擎，已用試算表驗證過，直接照搬。
- 培育系統的每週訓練(僅保留速度/耐力/加速/力量/根性/起跑/戰術/根性等訓練選項 + 休息，醫療與模擬賽可先跳過)。
- 馬匹成長(4種成長曲線類型)、潛力與評估(單一整體潛力)、狀態與健康。
- 比賽模擬的六階段位置值計算(比賽模擬.md)，比賽呈現採已定案的「純文字結算」。
- 基礎財務系統(收入/支出/負資產判定)，難度先只做「困難」一種(公式已經是雙難度，只是UI先不開放切換)。
- UI流程與遊戲迴圈.md 的「每週核心迴圈」與「比賽日流程」，逐匹委託管理開關、清單模式待辦事項。

## 簡化(先用簡化版本，之後再展開)
- 賽事分級：只做3級(新馬賽、地方一般賽、GI)，不做完整10級距，減少內容產出負擔，但驗證「低→高階賽事」的進程感受。
- 戰術系統：先保留「自由發揮」與「保存體力」兩種，驗證戰術對比賽結果有感即可，其餘6種戰術之後再加。
- 騎師：每匹馬固定配一名NPC騎師(依7項能力隨機生成一次)，不做賽前自由騎師3輪配對市場。
- 設施：馬房/各訓練場固定給Lv2，不開放升級，先驗證訓練公式而非經營深度。
- 隨機事件：只保留馬匹事件的正面「幸運訓練」與負面「疲勞加劇」兩項，驗證機制本身，其餘事件之後補齊。
- 賽道/場地：固定一座賽馬場、固定良好場地，不做天氣系統與場地狀況變動。

## 先跳過(v2以後再做)
- 完整競標拍賣先跳過；目前使用固定價格馬匹市場，玩家以零匹馬、200,000資金開局並自行購馬。
- 繁殖/遺傳系統(整個世代玩法留到有基礎迴圈驗證後再做，這是長線內容，不影響MVP要驗證的問題)。
- NPC馬主的完整決策邏輯(MVP用固定強度的「假對手馬」出賽即可，不需要真正跑買賣/訓練/財務的AI)。
- 馬主聯盟升降級制度、海外賽事、海外馬房、年度獎項評選。
- 訓練師/獸醫員工系統(MVP先讓玩家直接手動訓練，委託管理的UI開關可以先做但背後邏輯先簡化成「照人格權重固定分配」)。
- 特性系統、個性系統(數值影響有限，且會增加資料結構複雜度，先跳過)。

## MVP遊戲流程(精簡版)
1. 開局：玩家沒有馬匹，持有200,000資金，從固定價格市場自行建立馬房與聘用員工。
2. 每週：為每匹馬選擇訓練項目或休息(逐匹手動或委託管理)。
3. 每4週：系統開放1~2場可報名的比賽(依馬匹評級自動篩選可報名的賽事)，玩家決定是否參賽、選擇戰術。
4. 比賽日：純文字結算六階段位置值變化，公布名次、獎金、名氣變化。
5. 迴圈重複，觀察12~16週後：馬匹能力是否有感成長、資金是否合理增減、比賽名次是否隨訓練投入產生變化。

## 建議開發順序
1. 先做「數值引擎」：把訓練公式、比賽公式、比賽模擬的六階段計算寫成純邏輯層(無UI)，直接拿數值平衡試算.xlsx 的公式與測試馬數據做單元測試，確保程式算出的結果跟試算表一致。
2. 再做最小UI：馬房列表、訓練分配頁、比賽結果頁、簡易財務頁，串起數值引擎。
3. 內部跑幾輪12~16週的模擬遊玩(可以先用試算表模擬或直接玩最小UI版本)，驗證核心迴圈的手感，再決定下一步要從「簡化」或「先跳過」清單裡挑哪些內容補回來。
